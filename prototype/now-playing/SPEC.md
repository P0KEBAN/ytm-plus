# Now Playing — Photoshopモック再現仕様

作成・検証: 2026-09-06。Phase 5の単体プロトタイプ。**人間による見た目・動きの承認待ち**。

## 開き方と範囲

`index.html` をChromeで直接開く。ビルド、サーバー、追加ライブラリ、ログインは不要。
通常画面の「…」→「プロトタイプの確認」で状態を切り替える。
音声は流れない。時刻、曲長、同期タイミング、翻訳、追加2曲は確認用データ。

- `src/`、`manifest.json`、YouTube MusicのDOM/APIには接続も変更もしていない。
- 保存、通信、音声再生、拡張への組み込み、コミットは行わない。
- 初期画面の曲名・アーティスト表記・7行の歌詞は提供モックのまま。
- `?state=paused` などで状態を直接開ける。`?capture=1` は比較専用で、時計と背景を初期フレームに固定する。
- 全フォルダをまとめて扱うこと。HTMLだけを別の場所へコピーするとCSS/JS/素材が読めない。
- **`assets/artwork.png` は git に入っていない。** 実在のアルバムジャケットで他者の著作物のため、
  public リポジトリには置かない（`.gitignore` 対象）。実体は `private-docs/prototype-assets/artwork.png`。
  復元するには `cp private-docs/prototype-assets/artwork.png prototype/now-playing/assets/`。
  無い場合は自動的に抽象アートへ落ちるので、プロトタイプ自体は動く。

## 1. このUIが必要とする状態

以下は型の記述。実装はビルド不要のJavaScript。UIに必要な情報から定義し、YTMの構造へ合わせた型ではない。

```ts
type Repeat = 'NONE' | 'ALL' | 'ONE';
type LyricsStatus = 'ready' | 'loading' | 'empty' | 'error';
type Palette = { primary: string; secondary: string; shadow: string }; // #RRGGBB
type LyricLine = {
  id: string;
  at: number;                // 秒。昇順。表示側へ渡す前に時刻補正済みであること
  text: string;
  translation?: string;     // 同じ行IDに対応する訳。試作の訳は確認用
};
type Track = {
  id: string;
  title: string;
  artist: string;
  album: string;            // ジャケットの代替テキストにも使用
  artwork: string | null;   // URL。null時は配色による抽象的な代替画像
  palette: Palette;
  duration: number;         // 秒。この試作は既知の正の曲長のみ
  lines: LyricLine[];
};
type UIState = {
  trackIndex: number;       // Track[]内の現在曲
  position: number;         // 秒、小数可
  duration: number;         // Trackから取得
  mediaPaused: boolean;    // 再生が停止されているか
  playing: boolean;        // 通常の再生/停止アイコンを決める情報
  buffering: boolean;      // バッファリング中か。上2つの比較だけで推測しない
  volume: number;          // 0〜100の整数。UI音量スケール
  lastNonzeroVolume: number; // 1〜100。0からの消音解除で戻すローカル設定
  muted: boolean;          // 音量値と独立した消音
  repeat: Repeat;
  shuffle: boolean;
  lyricsStatus: LyricsStatus;
  activeLine: number;      // 時刻から導出。-1はまだ該当行なし
  follow: boolean;         // 自動追従 / 手動閲覧
  translationEnabled: boolean;
  view: 'lyrics' | 'queue';
  highContrast: boolean;  // 読みやすさ優先。初期false
  motion: boolean;        // 装飾背景を動かす。初期true、OSの動き低減が優先
};
```

| 状態 | 更新契機・使用箇所 |
| --- | --- |
| Trackとpalette | 前後移動・キュー選曲。ジャケット、曲情報、背景、歌詞、曲長を更新 |
| position | 試作時計、シーク、歌詞クリック。バーと現在行を更新 |
| mediaPaused / playing / buffering | 再生・停止・状態選択。再生アイコンと読み込み表示 |
| volume / muted | 「…」内の音量操作。音量数値をそのまま発行 |
| repeat / shuffle | ボタン操作。リピート1は数字、ON状態は点とアクセシブル名でも伝達 |
| lyricsStatus | 曲変更、状態選択、再試行。歌詞と空/取得中/エラー画面を切替 |
| activeLine | requestAnimationFrame内で時刻から導出。文字の大きさ、ぼかし、追従位置 |
| follow | ホイール、タッチ、歌詞のフォーカス、スクロールキーでfalse。復帰ボタン・行選択でtrue |
| translationEnabled | 「…」内の切替。行IDに付いた訳だけを表示 |
| view | 右下の2ボタン。歌詞/キューを切替 |
| highContrast / motion | 表示設定。保存せず、そのページだけに適用 |

重要な区別：`mediaPaused=false` は「音が実際に出ている」ことの証明ではない。
モックのローディングは `mediaPaused=false, playing=false, buffering=true`。
一時停止は `true, false, false`。通常再生は `false, true, false`。
Adapterもこの違いを保持する。音量を`video.volume`の0〜1へ線形変換しない。

キューの現在曲と一覧は`trackIndex`と`Track[]`から導出し、二重の状態を持たない。
歌詞の行座標、シークドラッグ中フラグ、モーダルの開閉、背景の色補間途中の値は表示内部の状態。

## 2. このUIが発行する操作

`document`上の`CustomEvent('player-action', { detail: { type, ...payload } })`が操作意図の出口。
同じ操作を試作内の処理が即座に反映する。実機の成功/失敗の応答や通信プロトコルは未実装。
外部からこのイベントを送ってUIを操作するAPIではない。

| type | payload | 意味・試作の結果 |
| --- | --- | --- |
| `play` / `pause` | なし | 再生/停止。ローディング中の停止も可能 |
| `seek` | `{ seconds: number }` | 0〜曲長に制限。ドラッグの確定、またはキー操作で発行 |
| `next` / `previous` | なし | 次/前の曲へ。手動選曲は末尾/先頭で循環 |
| `selectQueueItem` | `{ id: string }` | 曲IDによる選曲。現在曲の表示と背景色を更新 |
| `setVolume` | `{ value: number }` | 0〜100の整数。試作のスライダー操作中に反映 |
| `toggleMute` | なし | 正の音量は保持して消音切替。音量0時は直前の非ゼロ値へ戻す |
| `toggleShuffle` | なし | ON/OFF。ONで次曲は現在曲以外から選択 |
| `cycleRepeat` | なし | NONE → ALL → ONE → NONE |
| `setTranslationEnabled` | `{ enabled: boolean }` | 対応訳の表示/非表示 |
| `seekToLyricLine` | `{ id: string }` | 行IDの時刻へ移動し自動追従を再開 |
| `resumeLyricFollow` | なし | 現在行へ復帰。フォーカスは歌詞領域へ移す |
| `openQueue` / `closeQueue` | なし | 右側をキュー/歌詞へ切替 |
| `retryLyrics` | なし | 取得中を表示。試作は650ms後に成功する |
| `setHighContrast` | `{ enabled: boolean }` | 背景を暗くし、歌詞のぼかしを外す |
| `setMotion` | `{ enabled: boolean }` | 背景の装飾的な変形を停止/再開 |

「…」の開閉と試作状態選択はローカル表示操作で、再生エンジンの操作ではない。
設定の永続化はない。将来保存する場合もRAF中やドラッグ中に書き込まない。

### 操作規則

- ボタンはネイティブbutton。Tabで移動、Space/Enterで実行。
- シークはネイティブrange。矢印で1秒、Home/Endで先頭/末尾。画面の通常位置では左右キーで5秒移動。
- 入力欄・ボタン・設定モーダルの外ではSpaceで再生/停止。入力中のキーは横取りしない。
- 音量は矢印で1、Home/Endで0/100。音量0と消音は同一視しない。
- キューを開くと最初の曲へフォーカス。Tab、Shift+Tab、Enterで選曲。Escapeで歌詞へ戻り、キューの入口へフォーカスを戻す。
- 設定はネイティブdialog。内部にフォーカスを閉じ、Escape/閉じるで「…」へ戻す。
- 手動スクロール中は自動追従を止める。「現在の歌詞に戻る」で再開。
- 現在行は歌詞領域の上から128設計pxに置く。長い行は可変高さで折り返し、行座標を再計測する。
- 曲末尾：ONEは同曲先頭、ALLは次曲へ循環、NONEは一覧の最後で停止。
- ブラウザ非表示中は試作時計とRAFを停止する。実際の音声エンジンが進む場合の時刻は将来Adapterが供給する。

通常のCSSの太さ指定だけだと、このMacでは300がW0、400がW4に解決されたためである。
フォント自体の複製・同梱・ダウンロードはしない。

### 操作アイコン（2026-09-06 に差し替え）

**初回実装ではPSDのアイコンレイヤーを1倍のPNGとして書き出して使っていたが、全廃してインラインSVGへ置き換えた。**
PSDのアイコン自体がユーザーが配布サイトから仮に持ってきた素材であり、確定デザインではなかったため。

PNGを捨てた理由は見た目の好みだけではない。

1. 38×32px などの1倍PNGのため、Retinaや拡大時に輪郭がぼける
2. `filter: brightness(0) invert(1)` で白へ潰しているだけなので、状態による色分けができない
3. シャッフル/リピートが細い線画、前後送り/一時停止がベタ塗りで、線の重さが揃っていなかった

差し替え後の規則:

- 全アイコンを `viewBox="0 0 24 24"` の共通グリッドで描く。表示サイズはCSSの `width`/`height` だけで決める
- 主操作（前・再生/一時停止・次）は `.glyph.solid` = ベタ塗り＋`stroke-linejoin: round` で角を丸める
- 副操作（シャッフル・リピート・キュー）は `.glyph.stroked` = 線画、`stroke-width: 2.1`、端点と角は丸
- 色は `fill: currentColor` / `stroke: currentColor`。`.glyph { color: #fff }` の1箇所で決まる
- ボタンの中心座標はモックのまま変えていないため、アイコンの大きさを変えても配置はずれない
- 旧 `.next` / `.repeat` にあった `top: -3px` の微調整は削除した。共通グリッドで光学的に中心が揃うため不要になった

**踏んだ罠**: `hidden` は `HTMLElement` のプロパティで、`SVGElement` には存在しない。
`svg.hidden = true` は単に無関係なJSプロパティを生やすだけで要素は消えず、
**再生アイコンが一生表示されない**状態になっていた。`toggleAttribute('hidden', ...)` へ変更して解決。
念のため CSS 側にも `.glyph[hidden] { display: none }` を置いた。
`<img>` や `<span>` から SVG へ置き換えるときは同じ罠を踏むので注意。

### 色・背景レイヤー（2026-09-06 に方式を作り直した）

**初版はPSD背景を1枚のPNGとして書き出し、3x3の色行列で染め直していた。これは廃止した。**

廃止した理由。色行列は「元の3色を新しい3色へ写す」線形変換なので、
**元と大きく違う色合いのジャケットでは色が破綻する。**
このプロジェクトの視覚上の核は「アートワークの色に画面が染まる」ことなので、
そこが1曲でしか成立しないのでは意味がない。

作り直した根拠は、ユーザーがこの背景を作ったグラデーション生成サイトの出力CSS。
レシピそのものが手に入ったので、画像ではなくレシピを実装した。

```
background-color: #000F1D
radial-gradient(at 20% 26%, #019E9E 0px, transparent 62%)
radial-gradient(at 80% 22%, #2D4B4D 0px, transparent 62%)
radial-gradient(at 72% 80%, #000F1D 0px, transparent 62%)
radial-gradient(at 24% 76%, #AAB580 0px, transparent 62%)
（Duotone / Grain / スケール 77% / ゆがみ 59%）
```

4色はジャケットからスポイトで拾ったもの。**PNGの中央値サンプルより、こちらが正しい元の色。**

現在の実装:

- 4点の放射グラデーションをフラグメントシェーダーで生成する。
  重みは CSS の `COLOR 0px, transparent 62%` と同じ、中心から線形に消える形
- 重ね順は CSS と同じ（`background-image` は先頭が最前面）。奥から `spot3` → `spot0` の順に重ねる
- fbm ノイズで座標を歪ませ（`warpAmount` / `warpScale`）、さらに同じノイズで
  明暗を重ねて雲の濃淡を作る（`cloudAmount`）。歪ませるだけだと平坦に見えたため
- 粒は `gl_FragCoord` ベースのハッシュ。画面に固定され、煙と一緒には泳がない
- **スポットの座標は配色ではなく構図。曲が変わっても動かさない。変わるのは色だけ**

色の供給:

- `mock-data.js` の `palettes` が唯一の供給元。`player.js` がパレットのキーをそのまま
  `--art-<key>` へ流すので、`base` / `spot0`〜`spot3` を足すだけで背景へ届く
- `primary` / `secondary` / `shadow` はUI用（抽象ジャケット、リピート1のバッジ）。背景とは別系統
- 曲が変わると5色すべてを時定数500msで補間する
- **実ジャケットからの色抽出は未実装。** Phase 7 で実装する。今はモックの色を入力とする

WebGL が使えない場合:

- `style.css` の `body` に、同じレシピの静的版を `radial-gradient` で置いてある。
  canvas を透明にするだけでそちらが出るので、JS 側にフォールバック描画のコードは無い
- **座標を変えるときは `smoke.js` の `SPOTS` と `style.css` の body 背景を両方直すこと**

この作り直しで **`assets/smoke-textures.js`（4.7MB のdata URL埋め込み）が不要になり削除した。**
`prototype/` は 5.1MB から 416KB になった。

**未解決**: 明るいジャケットだと背景が明るくなり、白い歌詞とのコントラストが不足する。
低彩度パレットで実際に確認済み。「読みやすさを優先」設定では回避できるが、
既定でも破綻しない仕組み（抽出色の明度を抑える等）が Phase 7 で要る。

### 画面比率

ユーザーの回答：「比率を保ち、余白を調整する」。
`scale = min(viewportWidth / 1920, viewportHeight / 1080)`で、主画面を中央に配置する。
背景は常に全画面、右下切替は画面の右下に固定する。

| ビューポート | scale | 主画面の上下余白 | ジャケット |
| --- | --- | --- | --- |
| 1920×1080 | 1 | 0px | 603×598px |
| 1440×900 | .75 | 45px | 452.25×448.5px |
| 1100×700 | .5729167 | 40.625px | 約345.47×342.60px |

ジャケットの603:598という元レイヤーの比率を保持する。無断で正方形へ変形しない。
1100×700より小さい画面やスマートフォンの新レイアウトは今回の対象外。

## 3.5 調整パネル（tune.js・2026-09-06 追加）

**プロトタイプ専用の調整用UI。拡張本体へは持ち込まない。**

狙いは、見た目の微調整を「AIに言葉で何度も伝え直す」ラリーにしないこと。
背景の質感のように、粒の強さ・細かさ・煙の速さ・彩度の**組み合わせ**で決まるものは、
言葉のやりとりでは収束しない。人間がスライダーで決めた数値を1回渡す方が速い。

使い方:

1. `index.html?tune=1` で開く（または `Shift+T`）
2. スライダーで調整する。値は `localStorage`（キー `ytm-plus.tune`）に自動保存される
3. 「数値を書き出す」で、**既定値から変わった項目だけ**がテキストになる。これをAIへ渡す
4. AIが `smoke.js` の `defaults` と `style.css` の `.view-switch` へ焼き込む

設計上の約束:

- **パネルを開くまで、保存値は一切適用しない。** 通常表示のプロトタイプが調整値で汚れないため
- 既定値のままなら、パネル導入前とレンダリング結果が一致することを実測で確認した
  （1920×1080、DPR2 で最大差 1/255・平均差 0）。シェーダ側は既定値のとき演算そのものを飛ばしている
- 調整対象は2系統。背景は WebGL の uniform（`Smoke.setParams`）、右下の切替は CSS カスタムプロパティ
  （`--sw-bg` / `--sw-sel` / `--sw-blur` / `--sw-radius` / `--sw-btn-radius` / `--sw-h` / `--sw-w` / `--sw-pad` / `--sw-tint`）
- 「左右」ボタンでパネルを反対側へ移せる。パネルに隠れた部分を見るため

背景シェーダの uniform と既定値（2026-09-06 に人間がスライダーで決めた値）:

| uniform | 既定 | 意味 |
| --- | --- | --- |
| `spotRadius` | .62 | 各色の広がり。CSS の `transparent 62%` に対応 |
| `fieldScale` | 1.08 | 模様全体の拡大率 |
| `warpAmount` | .24 | ノイズで座標を歪ませる量 |
| `warpScale` | 2.0 | その歪みの細かさ |
| `warpSpeed` | 5 | 動きの速さの倍率 |
| `cloudAmount` | .22 | 雲の濃淡の強さ |
| `grainAmount` | .05 | 粒（ザラザラ）の強さ |
| `noisePixel` | 2 | 粒1つの大きさ(px)。小さいほど細かい |
| `saturation` / `brightness` / `contrast` | 1 / 1 / 1 | 発色 |

右下の切替の既定値も同じ手順で決めた（`--sw-bg` .16 / `--sw-sel` .18 / `--sw-blur` 5px /
`--sw-radius` 36px / `--sw-pad` 5px）。`--sw-radius` の 36px は、`border-radius` が
高さの半分で頭打ちになるため見た目には 28px 相当で、完全な丸を意味する。

## 4. 再現差・制約

- **完全な画素一致ではない。** 同じローカルフォントでもPhotoshopとChromeの文字ラスタライズ、端数座標、影の計算が異なる。
  初期1920px比較で、曲名と現在行の白い字の右端には約2px、アーティストの上下には約1pxの差が残る。
- 非現在行のぼかしはCSSで再実装した。PSDのスマートオブジェクトの最終ラスタとエッジ・濃さが完全には一致しない。
- CSSの影はPSDの数値を引き継いだが、Photoshopの「サイズ」とCSSのぼかし半径は同じ描画式ではない。
- 動く背景の形は静止モックだけでは指定されていない。初期フレームは元の煙を保持し、その後に変形する。
- 元モックには停止アイコン、ローディング、キュー、翻訳、長い曲名、設定画面がない。これらは下記の仮決め。
- フォントがインストールされていないMacではHiragino Sansへフォールバックし、幅や太さが変わる。
- WebGLが利用できない場合は元の煙を静止表示する。色変更はCSSのluminosity合成による簡易表現となり、通常の3色変換とは異なる。
- 本番接続時の非同期操作失敗、シーク応答待ち、独立した翻訳取得中/翻訳エラー、曲長不明、キューの取得失敗は未実装。
  現在の「歌詞取得エラー」や「読み込み中」を、それらの対応済みという意味に広げないこと。

### コントラスト

初期表示はモックの明るさと白文字を優先する。そのため、明るい左側の白文字はすべての場所で
4.5:1を満たすわけではない。既定のぼかした歌詞も、読みやすさのための設定ではない。

「…」→「読みやすさを優先」で、`#001018`の52%オーバーレイを背景に足し、全歌詞のぼかしと透過を解除する。
右下の切替も暗い背景へ変更する。フォーカスは白3px＋濃紺の外周で、明暗の背景双方で認識できる。
1440×900で前景だけを隠し、実際のブラウザ背景と白のコントラストを全画素で計算した。

## 5. 仮決めした点と理由

| 判断 | 仮決め・理由 |
| --- | --- |
| Apple Musicに近い構成 | 今回のユーザー説明を優先。旧文書の「模倣しない」を理由にモックを変えない |
| 常設要素 | モックどおり。「…」に音量・翻訳・読みやすさ・動き・試作状態確認をまとめた |
| 進捗 | モックに時刻表示がないため140/240秒とした。時刻はバーのhover/focus時だけ補助表示 |
| 原文と翻訳 | 原文48/45pxを保ち、訳を24pxで下に配置。翻訳ON時は末尾48設計pxをフェードさせて画面外の行の切断を和らげる。訳は確認用で正式な楽曲訳ではない |
| 長い曲名・アーティスト | 1行省略で再生制御の位置を保つ。全文はtitle属性、読み上げ、キューで参照できる |
| 長い歌詞 | 複数行に折り返し、曲名のように省略しない |
| キュー | 右側の歌詞領域を置き換える。新しい常設ボタンは増やさない |
| 初期リピート/シャッフル | NONE / OFF。ON状態は小さな点、ONEは数字を追加 |
| 追加曲の画像 | 提供されていないため、指定配色を使う抽象的な代替画像 |
| 自動追従 | 現在行を上寄りに保つ。行選択または復帰ボタンで再開 |
| 背景の動き | 約57秒/74秒のゆるい変形。最大変位は各軸約2.8%。速度の好みは人間レビュー対象 |
| 色の遷移 | 時定数500msの補間。約1.5秒で95%遷移。OSの動き低減では即時 |
| モックへの追加状態 | 選定済みデザインを使った最小限の試作。製品仕様の承認済み扱いにはしない |

## 6. 検証と性能

実際のChromeでファイルを直接開き、PNGと横並びにして自分で比較した。

**検証は自動化してある。`check.cjs` を実行すること（2026-09-06 に private-docs から
リポジトリ内へ移した。失うと作り直しが高くつくため）。**

```bash
YTM_PLAYWRIGHT=<playwrightのパス> node prototype/now-playing/check.cjs
```

playwright はこのプロジェクトの依存ではないので、場所を環境変数で渡す。
出力先の既定は `private-docs/phase5-verification/`（git 追跡外）。`YTM_OUT` で変えられる。
`checks.json` が操作検証の結果、`contrast.json` がコントラスト測定、
残りは各状態・各画面幅のスクリーンショット。

**見た目を変えたら必ずこれを通すこと。** ただし**これだけでは足りない**。
アイコンをSVG化したとき、`checks.json` の「pause button changes」は通っていたのに
再生アイコンが一度も表示されない不具合が残っていた。あの検証は `aria-label` の変化を
見ていて、実際の描画を見ていなかったためである。**必ずスクリーンショットを人間かAIの目で見ること。**

- 1920×1080で配置・背景を比較し、1440×900、1100×700でも撮影。
- 通常再生、停止、再生ローディング、歌詞取得中、歌詞なし、歌詞エラー、翻訳ON、長文、低彩度を表示して確認。
- 再生キー、3状態リピート、整数音量、シーク、消音、キュー選曲とフォーカス復帰、歌詞クリック、手動スクロール復帰、再試行を確認。
- `prefers-reduced-motion`で背景が静止することと、通常時に背景が変化することを、前景を除いたスクリーンショットで確認。
- 外部HTTP(S)リクエスト0、ブラウザJavaScriptエラー0。
- 補足検証：翻訳末尾のフェード、ローカルHTTPプレビュー、WebGL無効時の静止背景と色変更も成功。
- 既存の構文チェックとテスト：84 pass / 7 skip / 0 fail。

歌詞のRAFはキャッシュされた時刻配列を二分探索する。行の切替時だけclassを変更する。
DOM全体の再構築は曲変更と翻訳切替時だけ。行座標は行変更・翻訳・ResizeObserverによる変更時だけ読む。
バーのtransformは最大10Hz、時刻テキストとrange値は値が変わった時だけ更新する。
背景は同じRAFから最大30fpsでGPUへ描画命令を出す。RetinaでもキャンバスはCSS画素数に抑える。

計測はChromeヘッドレス上のJSコールバック時間であり、GPU実行時間や実ブラウザの総描画負荷ではない。
初回計測で同じ時刻文字列を100msごとに書き直す不要なレイアウトが見つかり、値が変わる場合だけの更新へ修正した。
最終計測（Chrome 152.0.7977.76）：145フレーム、平均0.048ms、p95 0.20ms、最大0.30ms。
別の1.5秒区間のレイアウトは4回、合計0.629ms。毎フレームのレイアウトではなく時刻表示等の変更に伴うもの。
測定値はこの環境のスナップショットで、他環境の性能保証ではない。詳細は`checks.json`。

人間が確認する項目：背景の速度、ノイズの強さ、文字の微細な差、歌詞追従の感触、追加状態の見た目。
このレビューが終わるまではPhase 5完了やAdapter接続開始としない。
